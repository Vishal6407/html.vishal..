1. Introduction

1.1 Purpose

This document specifies the functional and non-functional requirements of Myntra, an online fashion and lifestyle shopping platform available on web, Android and iOS. It is intended for developers, testers, project managers, UI/UX designers and stakeholders.

1.2 Scope

Myntra lets customers discover, compare and purchase apparel, footwear, accessories, beauty and home products from a wide range of brands and sellers. The system covers:

  • Customer-facing apps (web, Android, iOS)
  • Seller/brand portal for catalog and order management
  • Admin and operations console
  • Payment, logistics, returns and customer-support integrations

2.2 Product Functions (Summary)

  1. User registration, login and profile management
  2. Product browsing, search, filtering and recommendations
  3. Wishlist ("Wishlist") and bag (cart) management
  4. Checkout, coupons, offers and payments
  5. Order tracking, cancellation, returns and exchanges
  6. Ratings, reviews and size guidance
  7. Loyalty and membership programs (e.g., Myntra Insider)
  8. Seller catalog, inventory and order fulfillment tools
  9. Admin controls: campaigns, pricing rules, content, analytics
  10. Notifications and customer support

2.4 Operating Environment

  • Web: Latest versions of Chrome, Safari, Firefox, Edge
  • Android: Android 8.0 and above
  • iOS: iOS 14 and above
  • Backend: Cloud-hosted, containerized microservices
  • Network: Works on 3G or better; progressive loading for low bandwidth

2.5 Design and Implementation Constraints

  • Compliance with Indian taxation (GST invoicing), consumer and data-protection laws
  • PCI-DSS compliance for card payments; no raw card storage by Myntra
  • Support for English and major Indian languages (e.g., Hindi, Tamil)
  • Third-party payment and logistics API limits and SLAs

2.6 Assumptions and Dependencies

  • Users have internet access and a mobile number or email
  • Payment gateways, SMS providers and courier partners are available
  • Sellers supply accurate product data and images
  • Pincode serviceability data is maintained by logistics partners

4. Non-Functional Requirements

4.1 Performance

  • NFR-1: Page load (PLP/PDP) under 2 seconds on 4G for 95% of requests.
  • NFR-2: Search results returned within 500 ms for 95% of queries.
  • NFR-3: API p95 latency under 300 ms for core services (excluding third-party calls).
  • NFR-4: The system shall handle peak sale traffic of at least 10x normal load without degradation (autoscaling, queueing, caching).

4.2 Availability and Reliability

  • NFR-5: 99.9% monthly uptime for customer-facing services; higher targets for payment and order APIs.
  • NFR-6: No loss of confirmed orders; transactions must be atomic or compensating (saga pattern).
  • NFR-7: Graceful degradation: if recommendations fail, browsing and checkout continue.
  • NFR-8: Disaster recovery with RPO ≤ 5 minutes and RTO ≤ 1 hour for core data.

4.3 Security

  • NFR-9: All traffic over TLS 1.2+; data encrypted at rest.
  • NFR-10: Passwords (where used) stored with strong salted hashing; OTPs expire within minutes and are rate-limited.
  • NFR-11: Card data handled only by PCI-DSS compliant gateways; Myntra stores tokens only.
  • NFR-12: Protection against OWASP Top 10 (SQL injection, XSS, CSRF, etc.), bot and scraping abuse, and fraudulent orders.
  • NFR-13: Role-based access control and least-privilege for internal tools.

4.4 Privacy and Compliance

  • NFR-14: Collect and process personal data per the DPDP Act 2023 with explicit consent, purpose limitation and user rights (access, correction, erasure).
  • NFR-15: Maintain GST, invoicing and e-commerce disclosure requirements (country of origin, seller details, return policy).

4.5 Usability and Accessibility

  • NFR-16: Mobile-first, responsive design with consistent navigation.
  • NFR-17: Support for multiple languages and localized currency/format (INR).
  • NFR-18: Meet WCAG 2.1 AA guidelines where practicable (contrast, screen-reader labels, scalable text).
  • NFR-19: A new user shall be able to complete a purchase in under 5 minutes.

4.6 Scalability and Maintainability

  • NFR-20: Horizontally scalable stateless services; independent deployment per microservice.
  • NFR-21: Centralized logging, metrics, tracing and alerting.
  • NFR-22: CI/CD with automated tests; target code coverage of at least 80% for core services.
  • NFR-23: Backward-compatible, versioned APIs.

4.7 Portability and Compatibility

  • NFR-24: Consistent behavior across supported browsers and OS versions; app updates must support at least the last two major versions.

8. Acceptance Criteria (Samples)

  1. Login: Given a valid mobile number, when the user enters the correct OTP within the validity period, then the user is logged in and the session is created.
  2. Pincode check: Given an unserviceable pincode, when the user tries to checkout, then the system blocks placement and shows an alternative message.
  3. Payment failure: Given a failed payment, when the user retries, then no duplicate order is created and stock reservation is handled correctly.
  4. Return: Given a delivered item within the return window, when the user raises a return, then a pickup is scheduled and refund status is shown after quality check.
  5. Seller upload: Given a bulk CSV with invalid rows, when uploaded, then valid rows are processed and a downloadable error report is generated.
